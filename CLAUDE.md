# TabInk — notes for Claude

Remote Windows pen display: Galaxy Tab S10 FE (Kotlin) → Windows 11 host (C++20 core, C# .NET 10 UI), with a Python LaTeX OCR sidecar in v1.

## Source of truth
- `docs/architecture.md` is the design. `docs/protocol-v1.md` is the wire contract. If code and spec disagree, flag it. Don't silently pick one.
- Current phase and open decisions: `docs/roadmap.md`. Don't build features from a later phase before the current gate passes.

## Hard rules (from the design)
- Never drop or reorder pen samples. Send historical `MotionEvent` samples before the current one. Never inject `PREDICTED` samples.
- Pen down/up/cancel must never be lost. On disconnect or a mapping-epoch change, synthesize pen-up and cancel the stroke. Never teleport.
- The pen channel never waits on video: separate sockets, threads and queues. Shed video, never pen transitions.
- Coordinates are in **physical** virtual-desktop pixels (per-monitor DPI v2), and the origin may be negative. **Exception found in P0.3:** `InjectSyntheticPointerInput` for `PT_PEN` takes pixels *local to the one display the pen is mapped to* and silently drops points elsewhere. Convert at the injection boundary with a measured mapping (`windows/tests/pen-diagnostics/pen_space.*`). Open decision D7.
- A successful `InjectSyntheticPointerInput` return doesn't mean the input was delivered. Verify with the self-test or a captured frame.
- No kernel driver, no WinTab, no Session 0 service in MVP/v1.
- Every channel uses TLS, even USB. Never open an unauthenticated injection port. Don't inject into elevated, locked, secure-desktop or unexpected windows.
- Don't log screen content, notes or LaTeX by default.
- Don't copy code from SuperDisplay or spacedesk. Check licenses (including model weights) before reusing upstream code.

## Environment
- Windows 11, PowerShell/Git Bash. MSVC via `vcvars64.bat` (VS Build Tools 2026). Use Python 3.12 for OCR (`py -3.12`).
- Hybrid GPU (Intel + NVIDIA): capture and encode must share a D3D11 adapter.
- Setup status: `docs/dev-setup.md`.

## Build / test commands
- OCR tests (from `recognition/`, in a py3.12 venv with `requirements/dev.txt`): `python -m pytest -q`
- Docker runs inside WSL, not on Windows PATH: `wsl -e sh -c 'cd /mnt/c/Users/abhin/Documents/TabInk && docker compose build ocr'`
- OCR engines need separate venvs/images: their pins conflict. Lock files in `recognition/requirements/*.txt` are generated by `uv pip compile`. Never hand-edit them.
- The Windows host never goes in Docker.
- Android (from repo root, via WSL docker): `docker compose --profile android run --rm android-build ./gradlew :penlogger:testDebugUnitTest :penlogger:assembleDebug`. The build-tools/compileSdk in `android/*/build.gradle.kts` must match `docker/android-build/Dockerfile`, or AGP re-downloads the SDK on every run.
- Windows (from repo root, PowerShell/cmd): `windows\build.cmd test` builds `windows\out\pen_diag.exe` + `unit_tests.exe` with MSVC and runs the unit tests. `windows\out\pen_diag.exe self-test` is the automated end-to-end pen check. It injects into its own window on the interactive desktop, so it can't run in CI.
